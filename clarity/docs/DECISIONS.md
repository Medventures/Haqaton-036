# Decision log

## 2026-09-30 — standalone hackathon prototype

- **Decision:** build Clarity as a separate project for Diagnostic Companion.
- **Reason:** the hackathon asks for a narrow one-procedure journey; a clean boundary makes the demo easier to review and avoids coupling unrelated systems.
- **Boundary:** TOMO24 remains a separate product. No code, data, identity, or infrastructure is reused here.

## 2026-09-30 — demo route: contrast-enhanced brain MRI

- **Decision:** use this route as the provisional example in the interface.
- **Reason:** it demonstrates pre-visit questions, prep, a reminder, result explanation, and human follow-up in one journey.
- **Caveat:** this choice and its sample wording are not clinic-approved clinical protocol. Replace/validate with the organizers and a named clinician.

## 2026-09-30 — local-only simulation

- **Decision:** keep the prototype browser-only and use synthetic report text.
- **Reason:** it enables a no-credentials hackathon demo without transmitting health information.
- **Consequence:** actions are not real bookings, reminders, staff requests, or AI interpretations. The current state is not a secure health record.

## 2026-09-30 — no repository license chosen

- **Decision:** do not add a software license without the owner's instruction.
- **Reason:** publishing source does not itself grant redistribution rights; a license should be chosen intentionally.

## 2026-09-30 — v2: backend, ИИ-аватар и метрики

- **Decision:** добавить Fastify-backend с детерминированным ядром правил (`server/domain`) и единым сервисным слоем; фронтенд берёт состояние с сервера вместо `localStorage`.
- **Reason:** цепочка кейса (проверка → подготовка → напоминание → заключение → запись) и 4 метрики требуют общего состояния, событий и очереди координатора.
- **Consequence:** хранилище — JSON-файл за интерфейсом `store.ts`; для пилота заменить на PostgreSQL.

## 2026-09-30 — LLM через OpenAI-совместимый API

- **Decision:** «мозг» аватара — открытая модель (по умолчанию Qwen2.5-72B-Instruct) через OpenAI-совместимый API; провайдер задаётся тремя переменными окружения.
- **Reason:** запрос владельца — легко развернуть на сервере без GPU; требование Green Clinic — open source. Один и тот же адаптер работает с OpenRouter/Together/Groq и с собственным vLLM/Ollama клиники.
- **Guardrail:** LLM не принимает медицински значимых решений; без ключа всё работает на правилах. Для реальных данных пациентов провайдер и юрисдикцию должен утвердить privacy-владелец.

## 2026-09-30 — образ аватара

- **Decision:** 2D SVG-робот-медсестра по референсу владельца, зелёный крест вместо красного, постоянный бейдж «ИИ-помощник · не врач».
- **Reason:** дружелюбный образ без имитации человека-врача; красный крест — охраняемая эмблема.

## 2026-09-30 — голос через Web Speech API

- **Decision:** TTS/STT браузера для прототипа, микрофон — только после предупреждения о приватности.
- **Reason:** ноль установок. В пилоте STT переносится на сервер клиники (Whisper/Vosk).

## 2026-09-30 — тревожность заключения определяют правила

- **Decision:** словарь маркеров трёх уровней с обработкой отрицаний; LLM только перефразирует.
- **Reason:** предсказуемость, тестируемость, аудит. Пропуск тревожной формулировки из-за «творчества» модели недопустим.

## 2026-09-30 — v3: голосовой разговор, агент, вход через Google, знакомство, геймификация

- **Голос:** режим «звонка» с автоматическим циклом «говорит → слушает». Причина: пожилым пациентам и людям с низкой цифровой грамотностью проще говорить, чем печатать.
- **Разговорный агент:** LLM видит контекст маршрута и базу знаний и может запускать действия только из белого списка с серверной валидацией. Флаги, рСКФ, тревожность и эскалации по-прежнему решают правила.
- **Модель по умолчанию:** Llama 3.3 70B через OpenRouter (0,5–1 с против 5–9 с у Qwen2.5-72B). Альтернатива под Apache-2.0 оставлена в `.env.example`. Лицензия Llama 3.3 — «open weights» с ограничениями; если Green Clinic требует строго OSI-лицензию, выберите Qwen2.5.
- **Вход через Google:** OIDC Authorization Code + PKCE без сторонних библиотек, серверные сессии с хэшем токена, роли через `STAFF_EMAILS`. Демо-вход оставлен для защиты и выключается одной переменной.
- **Знакомство после регистрации:** собираем только то, что нужно маршруту (возраст и пол для CKD-EPI и вопросов о беременности, время МРТ, опасения для советов, настройки доступности) и два явных согласия.
- **Геймификация:** звёзды и значки только за организационные действия; ничего за медицинские показатели, никаких рейтингов, штрафов и серий дней (roadmap, этап 9).

## 2026-09-30 — v4: казахский язык, реалистичный аватар, открытые голоса

- **Двуязычность ru/kk.** Язык хранится в профиле пациента и применяется к интерфейсу, сценарию диалога, LLM и синтезу речи. Серверный контент хранится на русском, казахский перевод применяется на выходе (localizeState). Тексты для персонала — на русском. Казахский медицинский перевод — черновой и требует вычитки клиническим редактором.
- **LLM для казахского:** Llama 4 Maverick (на тестовой реплике — наиболее естественный казахский среди открытых моделей, ~1,4 с). Русский — Llama 3.3 70B.
- **Озвучка:** Piper-голоса через sherpa-onnx (Apache-2.0) на сервере — у браузеров нет казахских голосов, а русские звучат роботизированно. Модели скачиваются скриптом и не хранятся в Git.
- **Реалистичный аватар «Аружан»:** по запросу владельца. Портрет вымышленного человека сгенерирован один раз моделью изображений (Gemini Image через OpenRouter) — это ассет, а не зависимость времени выполнения. Противоречие с принципом roadmap «не использовать реалистичный образ» снимается так: постоянная метка «ИИ/ЖИ», представление как «ИИ-помощник, не врач», вымышленная внешность, робот Клэри доступен как альтернатива.
- **Липсинк по звуку:** анализ спектра воспроизводимого аудио вместо имитации — рот совпадает с реальной речью на любом языке без фонемных таймингов.
- **Орнамент:** «қошқар мүйіз» как знак уважения и благополучия; используется деликатно, чтобы не отвлекать от медицинского содержания.

## 2026-09-30 — v5: документы пациента

- **Анализы:** распознавание фото через vision-модель, PDF через pdfjs, текст — правилами; обязательная проверка значений пациентом до анализа (roadmap, этап 7). Статус показателя — только относительно референса из бланка; нет референса — не сравниваем. Критические значения — узкий список общепринятых «панических» порогов → срочная задача координатору и совет связаться с врачом.
- **Заключение:** распознанный текст показывается пациенту на проверку перед объяснением. Вопросы по своим документам ассистент отвечает с контекстом документа, без диагнозов.
- **Запись:** при тревожных находках — предложение ближайшего слота с явным согласием («да»); смена темы сбрасывает ожидание подтверждения.
- **Приватность:** фото документов отправляются vision-модели через OpenRouter — для реальных данных нужен провайдер в согласованной юрисдикции или собственная модель.
