# ИИ-аватар Клэри: образ, диалог, безопасность

## 1. Образ

Референс — робот-медсестра: белый шлем с медицинским чепчиком, чёрный глянцевый визор со светящимися голубыми глазами и улыбкой, «наушники» со светящимися кольцами, белый халат, голубая форма, стетоскоп.

Принципиальные решения:

| Решение | Почему |
| --- | --- |
| Робот, а не человек | Пациент не должен принять ИИ за врача (см. [DEVELOPMENT_ROADMAP §2](DEVELOPMENT_ROADMAP.md)). Бейдж «ИИ-помощник · не врач» виден всегда |
| Зелёный крест вместо красного | Красный крест на белом фоне — охраняемая эмблема (Женевские конвенции), её нельзя использовать в продуктах клиник. Зелёный — цвет Green Clinic |
| SVG, а не видео и 3D | 0 КБ ассетов, чёткость на любом экране, мгновенная загрузка, управление мимикой из кода, тёмная и светлая темы |
| Без «говорящего лица» реального человека | Этика и доверие: нет имитации сотрудника |

Анимации (`src/assistant/Avatar.tsx`, `src/clarity.css`):

- **idle:** лёгкое «парение», пульсация модуля на груди, случайное моргание каждые 2–5 с, глаза следят за курсором;
- **speaking:** губы открываются по амплитуде (колебание + всплески на границах слов из `onboundary`), лёгкие кивки, пульсация «наушников»;
- **listening:** голова наклонена, глаза шире, «наушники» пульсируют зелёным;
- **thinking:** взгляд вверх, наклон головы, три точки на визоре;
- **happy / concerned:** форма глаз, бровей и рта; `concerned` — при критичных флагах и тревожном заключении;
- `prefers-reduced-motion` отключает все анимации.

## 2. Голос

`src/hooks/useSpeech.ts`, Web Speech API:

- **TTS:** русский голос (Milena на macOS, Google русский и др.), rate 1.03, pitch 1.12. Текст адаптируется для произношения: «МРТ» → «эм-эр-тэ», единицы измерения. Если голоса нет — анимация губ по длине текста.
- **STT:** `SpeechRecognition` ru-RU с промежуточными результатами (видны в поле ввода). **Приватность:** в Chrome аудио уходит на серверы Google, поэтому перед первым включением микрофона пациент видит предупреждение. Для пилота — Whisper (whisper.cpp) или Vosk на сервере клиники; интерфейс хука это позволяет.
- Субтитры реплики показываются рядом с аватаром, голос выключается одной кнопкой (настройка запоминается).

## 2a. Голосовой разговор («звонок»)

`src/assistant/VoiceCall.tsx`. Полноэкранный режим, в котором не нужно нажимать кнопки:

```text
согласие (приватность STT) → Клэри говорит (очередь предложений, субтитры)
   → onEnd → слушает (волны, «Слушаю вас…», промежуточный текст)
   → фраза → mode:"voice" → короткий ответ агента → говорит → …
```

- **Перебить:** кнопка, тап по аватару или пробел.
- **Тишина:** после двух пустых попыток — пауза «нажмите, чтобы говорить», микрофон не слушает бесконечно.
- **Кнопки и карточки** (слоты записи, сводка проверки) остаются видимыми под аватаром — голос не заменяет визуальное подтверждение.
- **Ввод текстом** внутри звонка — если шумно или нет микрофона.
- **Голосовой режим ответов:** агент отвечает 1–3 короткими предложениями, без списков.
- **Задержка:** Llama 3.3 70B через OpenRouter с `provider.sort=latency` отвечает за 0,5–1 с; сценарные шаги работают на правилах мгновенно.

## 3. Мозг: гибридная архитектура

```text
Реплика пациента (текст/голос/кнопка)
  │
  ├─► safety.detectEmergency ──► 103/112 + срочная задача      (всегда первым, без LLM)
  │
  ├─► Этап сценария (state machine в dialog.ts)
  │     screening → lab_has → lab_value → lab_date → summary
  │     report_input · booking_pick → booking_confirm · cancel_reason
  │     └─ nlu.parseAnswer / parseCreatinine / parseLabDate   (правила)
  │        └─ не распознано → llm.classify (JSON)             (LLM, опционально)
  │
  ├─► Намерение: nlu.detectIntent → действие маршрута
  │     └─ не распознано → llm.classify
  │
  └─► Свободный вопрос
        ├─ safety.isClinicalDecisionRequest → вежливый отказ + координатор/врач
        ├─ knowledge.retrieve (карточки с версией)
        │    └─ нет карточки → «не знаю, передать координатору?»   (без выдумок)
        └─ llm.groundedAnswer(только по карточкам) → safety.violatesOutputPolicy
             └─ нарушение/недоступна → текст карточки как есть
```

**Разговорный агент** (`server/assistant/agent.ts`) получает:
- контекст маршрута: имя, возраст, пол, первое ли МРТ, уровень волнения, опасения, визит, статус проверки, анализ, подготовку, напоминания, заключение, записи, уровень прогресса;
- всю базу знаний клиники (18 карточек с версиями);
- последние 10 реплик диалога;
- белый список действий: `screening_start`, `prep`, `reminder_menu`, `visit_confirm`, `visit_cancel_start`, `report_start`, `booking_start{specialty}`, `human`, `status`.

Модель возвращает JSON `{reply, action}`; сервер проверяет его zod-схемой и фильтром безопасности и только после этого выполняет действие. Запрещено выдумывать внешние факты (погода, новости): это проверено на реальной модели.

**Что делает LLM:** ведёт живой диалог, понимает свободную речь, перефразирует ответы из утверждённой базы знаний, пересказывает заключение простыми словами.

**Что LLM не делает никогда:** не определяет флаги противопоказаний, рСКФ, тревожность заключения, специальность для записи и эскалации. Всё это — детерминированные правила в `server/domain/`, покрытые тестами.

### Защиты

1. Системный промпт: не врач, не диагноз, только по фрагментам, 2–4 предложения, 103/112 при симптомах.
2. Фильтр ответа (`violatesOutputPolicy`): «у вас опухоль», «можете отменить лекарства», дозировки, «вам можно контраст», ложные заверения, «я врач» → ответ отбрасывается.
3. Маскирование PII перед отправкой в модель: телефоны, email, ИИН.
4. Бюджет: `max_tokens` 350–400, `temperature` 0.2, таймаут 30 с, проверка здоровья API раз в минуту.
5. Метка «ИИ» на репликах, сформулированных моделью; источник и версия карточки знаний под ответом.

## 4. Объяснение заключения

`server/domain/report.ts`:

1. Текст делится на предложения, предложения — на клаузы.
2. **Отрицания** снимают находку в пределах клаузы: «не выявлено», «без признаков», «отсутствуют». «Не исключается» и «нельзя исключить» — это **подозрение**, а не отрицание.
3. **Тревожные маркеры** трёх уровней:
   - `urgent` — кровоизлияние, острая ишемия, смещение срединных структур, масс-эффект, окклюзионная гидроцефалия, «срочная консультация» → срочная задача координатору, запись с ближайшего дня, советы при симптомах;
   - `significant` — образование, метастаз, аневризма, демиелинизация, патологическое накопление контраста, аденома гипофиза, «подозрение на», «рекомендована консультация» → предложение записи;
   - `minor` — глиоз, кисты, пазухи, атрофия → обсудить на плановом приёме.
4. Специальность — от самого серьёзного маркера.
5. Словарь из 30+ терминов, вопросы врачу и обязательная оговорка «интерпретирует лечащий врач».

## 5. Как расширять

- **Новый вопрос анкеты:** `server/domain/protocol.ts` → `SCREENING`, правила `onYes` / `onUnknown`, `personalPrep`.
- **Новая карточка знаний:** `server/assistant/knowledge.ts` (ключевые слова и версия).
- **Новый маркер или термин:** `RED_FLAGS` / `GLOSSARY` + тест в `tests/domain.test.ts`.
- **Другой маршрут (колоноскопия):** новый файл протокола, база знаний и словарь; оркестратор не меняется.
- **Другой голос или STT:** заменить реализацию `useSpeech` (интерфейс `speak/listen` сохранится).
